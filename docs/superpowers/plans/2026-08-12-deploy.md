# Deploy Implementation Plan (Plan 6 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Split execution:** Tasks 1–8 are repo work an agent can do alone. Tasks 9–14 run against the live VPS and GitHub settings — they need the human at the keyboard (passwords, DNS panel, GitHub PAT). Do not let a subagent "simulate" a VPS task.

**Goal:** `https://pastoral.jesuslab135.com` serving the public calendar, the admin panel, and the .ics feeds from the IONOS VPS at **198.71.54.171**, redeployed automatically on every green push to `main`.

**Architecture:** Two GHCR images — `ghcr.io/jesuslab135/pastoral-backend` (one Go image carrying the `api`, `worker`, and `setup` binaries; compose picks the entrypoint per service) and `ghcr.io/jesuslab135/pastoral-web` (Caddy + baked `frontend/dist`). One `docker-compose.prod.yml` on the VPS at `/opt/pastoral` runs web/api/worker/postgres/redis. `deploy.yml` builds+pushes on CI-green `main`, SSHes in, rewrites `TAG=` in `/opt/pastoral/.env`, pulls, ups, health-checks through Caddy, and rolls back to the previous tag on failure.

**Tech Stack:** Docker multi-stage builds (golang:1.23-alpine → distroless/static, node:22-alpine → caddy:2-alpine), Caddy auto-HTTPS, GitHub Actions (`docker/build-push-action`, `appleboy/ssh-action`), GHCR.

**Spec:** `docs/superpowers/specs/2026-08-10-pastoral-calendar-design.md` §10 (CI/CD), §12 (VPS runbook), §13 (risks).

## Global Constraints

- **Commit messages: plain conventional commits. NEVER add `Co-Authored-By` or any mention of Claude/Anthropic/AI. (Explicit user requirement.)**
- Backend `go.mod` directive stays `go 1.23.x`; the build image is pinned `golang:1.23-alpine` to match CI.
- **Never weaken CI**: `ci.yml` is not touched by this plan except nothing — deploy is a separate workflow gated on CI's conclusion.
- Pin every new third-party action to a version (`appleboy/ssh-action@v1.2.0`, `rhysd/actionlint:1.7.4` for validation); official `actions/*` and `docker/*` stay on their major tags like the existing `ci.yml`.
- `project/` is design reference — never modify it.
- All user-facing copy in Spanish; ops files (Dockerfile, Caddyfile, workflows) are code and comment in English like the rest of the repo.
- Existing checks stay green after every task: `go test ./... -count=1` (from `backend/`), `npm test` + `npx astro check` + `npm run build` (from `frontend/`). No task here touches app code, so a red suite means the task leaked.
- **Secrets never enter git**: no VPS password, no `AUTH_SECRET`, no SMTP creds, no filled `.env` — only `deploy/.env.example` with `CHANGE_ME` markers. The VPS password the user holds is treated as leaked (it was shared in chat, twice) and is rotated in Task 9.
- **`PUBLIC_BASE_URL=https://pastoral.jesuslab135.com` is permanent once parishioners subscribe** — every .ics UID is minted from its host; changing it later duplicates every event on every subscribed phone.
- `app.jesuslab135.com → 74.208.73.82` is an **unrelated server. Never touch its DNS record or that machine.** The calendar VPS is `198.71.54.171`.

## Deliberate deviations from the spec (reality won)

| Spec §10/§12 says | This plan does | Why |
|---|---|---|
| `migrate` one-shot compose service, `docker compose run --rm migrate` in deploy | **No migrate service.** | `cmd/api` already runs `store.MigrateLocked` on every boot (embedded goose + advisory lock); the worker refuses to start until `goose_db_version` exists. A second migration path could only disagree with the first. |
| `/opt/pastoral/data/{postgres,redis,caddy}` bind mounts | **Named volumes** (`pgdata`, `redisdata`, `caddydata`) | Avoids the postgres-chown-on-bind-mount failure class entirely and lets the same compose file run the local smoke test on Windows (Task 6). Backup story unchanged: the documented `pg_dump` one-liner. |
| "password … changed on first login" | Generated párroco password is **kept** (password manager) | There is no change-password endpoint: `PUT /admin/users/{id}` does not accept a password (only create does). Building one is app work, out of deploy scope — noted for the backlog. |

Two Plan-5 handoff items are folded in because they are Caddy's job: the **`/admin` deep-link fallback** (`try_files`) and **`X-Robots-Tag: noindex`** on `/admin*`.

## File structure (what this plan creates)

```
backend/Dockerfile                  multi-stage Go build → distroless, 3 binaries
frontend/Dockerfile                 npm ci + astro build → caddy:2-alpine with dist baked at /srv
frontend/.dockerignore              keeps node_modules/dist/.astro out of the build context
deploy/Caddyfile                    site config; bind-mounted on the VPS (config change ≠ rebuild)
deploy/docker-compose.prod.yml      the 5 prod services; copied to /opt/pastoral/docker-compose.yml
deploy/.env.example                 every runtime variable, documented, CHANGE_ME markers
.github/workflows/deploy.yml        build → push GHCR → SSH deploy → health check → rollback
README.md                           new "Despliegue" section (modified)
docs/superpowers/plans/2026-08-10-roadmap.md   Plan 6 progress (modified, end of run)
```

**Contracts every task must agree on** (referenced throughout, defined once here):

- Image names: `ghcr.io/jesuslab135/pastoral-backend` and `ghcr.io/jesuslab135/pastoral-web`, tags `latest` + full commit SHA.
- Backend image binaries: `/app/api` (ENTRYPOINT), `/app/worker`, `/app/setup`.
- Web image content: `frontend/dist` at `/srv`; Caddyfile expected at `/etc/caddy/Caddyfile` (mounted, not baked).
- Compose interpolation variables (live in `/opt/pastoral/.env`): `TAG` (image tag, rewritten by deploy), `SITE_ADDRESS` (Caddy site address, default `pastoral.jesuslab135.com`), `HTTP_PORT`/`HTTPS_PORT` (host ports, default 80/443), `POSTGRES_PASSWORD`.
- App environment (same `.env`, passed via `env_file`): exactly the variables `backend/internal/config/config.go` reads.
- VPS layout: `/opt/pastoral/{docker-compose.yml,Caddyfile,.env,.tag.prev}`, owned by user `deploy`.
- Deploy network: fixed subnet `172.28.0.0/24` so `TRUSTED_PROXY` can be a stable CIDR.

### Task 2: Backend image

**Files:**
- Create: `backend/Dockerfile`

**Interfaces:**
- Consumes: `backend/cmd/{api,worker,setup}` — all three import `time/tzdata` (api/worker) or need no TZ (setup), so a distroless base with no zoneinfo works. CGO is unused.
- Produces: image with `/app/api` (ENTRYPOINT), `/app/worker`, `/app/setup` — compose (Task 5) and the runbook (Task 13) invoke the latter two via `entrypoint:`/`--entrypoint`.

- [ ] **Step 1: Write `backend/Dockerfile`**

```dockerfile
# One image carries the three binaries (api, worker, setup); compose picks
# the entrypoint per service, so every deploy ships one backend artifact.
FROM golang:1.23-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/api ./cmd/api \
 && CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/worker ./cmd/worker \
 && CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/setup ./cmd/setup

# distroless/static: CA certs for SMTP TLS, /etc/passwd for nonroot, no shell.
# The binaries embed tzdata themselves (time/tzdata), so PARISH_TZ resolves.
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/ /app/
ENTRYPOINT ["/app/api"]
```

### Task 4: Caddyfile

**Files:**
- Create: `deploy/Caddyfile`

**Interfaces:**
- Consumes: API on `api:8080` (compose service name, Task 5); static site at `/srv` (Task 3); `SITE_ADDRESS` env var on the web container (Task 5 sets it, default `pastoral.jesuslab135.com`).
- Produces: routing contract — `/api/*`, `/healthz`, `/calendario.ics`, `/calendario/*` → Go API; `/admin*` → static with SPA fallback + `X-Robots-Tag`; everything else → static. Tasks 6, 7, 12, 14 verify against exactly these paths.

- [ ] **Step 1: Write `deploy/Caddyfile`**

```
{
	email lidering.esteban@gmail.com
}

# SITE_ADDRESS lets the local smoke test run the same file as production
# (":80" locally, the real domain on the VPS).
{$SITE_ADDRESS:pastoral.jesuslab135.com} {
	encode zstd gzip

	@backend path /api/* /healthz /calendario.ics /calendario/*
	handle @backend {
		reverse_proxy api:8080
	}

	# The admin shell pre-renders /admin, /login, /eventos, /difusion and
	# /equipo; try_files makes any deeper client-side route land on the shell
	# instead of a 404 on hard refresh. The panel must never be indexed.
	handle /admin* {
		header X-Robots-Tag "noindex, nofollow"
		root * /srv
		try_files {path} {path}/ /admin/index.html
		file_server
	}

	handle {
		root * /srv
		@assets path /_astro/*
		header @assets Cache-Control "public, max-age=31536000, immutable"
		file_server
	}
}
```

`docker run --rm -v "${PWD}\deploy\Caddyfile:/etc/caddy/Caddyfile:ro" caddy:2-alpine caddy validate --config /etc/caddy/Caddyfile`
Expected: `Valid configuration`.

### Task 7: deploy.yml

**Files:**
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: `ci.yml`'s workflow name `CI` (the `workflow_run` gate); secrets `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY` (created in Task 11); `/opt/pastoral/.env`'s `TAG=` line and `docker-compose.yml` (Task 10).
- Produces: images tagged `latest` + SHA on GHCR; `/opt/pastoral/.tag.prev` (rollback state).

- [ ] **Step 1: Write `.github/workflows/deploy.yml`**

```yaml
name: Deploy

# Deploys only after the CI workflow finishes green on main; manual dispatch
# is the escape hatch (it deploys the current main HEAD).
on:
  workflow_run:
    workflows: [CI]
    types: [completed]
    branches: [main]
  workflow_dispatch:

concurrency:
  group: production-deploy
  cancel-in-progress: false

permissions:
  contents: read
  packages: write

jobs:
  build:
    if: github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success'
    runs-on: ubuntu-latest
    outputs:
      sha: ${{ steps.meta.outputs.sha }}
    steps:
      - name: Resolve deployed commit
        id: meta
        run: echo "sha=${{ github.event.workflow_run.head_sha || github.sha }}" >> "$GITHUB_OUTPUT"
      - uses: actions/checkout@v4
        with:
          ref: ${{ steps.meta.outputs.sha }}
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - name: Build and push backend image
        uses: docker/build-push-action@v6
        with:
          context: backend
          push: true
          tags: |
            ghcr.io/jesuslab135/pastoral-backend:latest
            ghcr.io/jesuslab135/pastoral-backend:${{ steps.meta.outputs.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
      - name: Build and push web image
        uses: docker/build-push-action@v6
        with:
          context: frontend
          push: true
          tags: |
            ghcr.io/jesuslab135/pastoral-web:latest
            ghcr.io/jesuslab135/pastoral-web:${{ steps.meta.outputs.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://pastoral.jesuslab135.com
    steps:
      - name: Deploy over SSH
        uses: appleboy/ssh-action@v1.2.0
        env:
          NEW_TAG: ${{ needs.build.outputs.sha }}
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          envs: NEW_TAG
          script_stop: true
          script: |
            cd /opt/pastoral
            grep -oP '(?<=^TAG=).*' .env > .tag.prev || echo latest > .tag.prev
            sed -i "s|^TAG=.*|TAG=${NEW_TAG}|" .env
            docker compose pull
            docker compose up -d
            docker image prune -f
      - name: Health check through Caddy
        run: |
          sleep 10
          curl --fail --silent --show-error \
               --retry 12 --retry-delay 10 --retry-all-errors \
               https://pastoral.jesuslab135.com/healthz
      - name: Roll back to previous tag
        if: failure()
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.VPS_HOST }}
```
