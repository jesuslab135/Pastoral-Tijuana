# Calendario Pastoral — Implementation Roadmap

Spec: `docs/superpowers/specs/2026-08-10-pastoral-calendar-design.md`

Six plans, executed in order. Each produces working, independently testable software.

| # | Plan | Delivers | Status |
|---|------|----------|--------|
| 1 | **Backend Foundation** (`2026-08-10-backend-foundation.md`) | Repo scaffold, dev Docker env, all 8 tables + seeds (seasons 2026–27, groups), public read API (events/seasons/groups), .ics feeds, healthz, backend CI | Planned |
| 2 | Auth & Admin API | users/sessions, login + magic link, admin CRUD (events, channels, users), publish/unpublish writing outbox rows | Pending |
| 3 | Difusión Engine | outbox relay, asynq fanout, stub WhatsApp + SMTP senders, broadcasts settling, retry, quiet hours/debounce/dedupe/cancellation rules | Pending |
| 4 | Public Frontend | Astro project, design tokens, static shell, Preact calendar island (month/week/agenda, filters, day panel), frontend CI | Pending |
| 5 | Admin Frontend | React island, Redux Toolkit + RTK Query (axios), Login/Eventos/Difusión/Equipo screens | Pending |
| 6 | Deploy | prod compose + Caddy, GHCR images, deploy.yml, VPS runbook execution (DNS check, hardening, first deploy) | Pending |

Rule: each plan is written in full (bite-sized TDD tasks) only when the previous plan is complete, so it reflects the actual codebase.

**Spec refinement recorded during planning:** cancellation with notify requires the event to remain in the .ics feed with `STATUS:CANCELLED`, so `events` gains a `cancelled_at timestamptz NULL` column (soft cancel). `DELETE ?notify=true` sets `cancelled_at`; `?notify=false` hard-deletes. Public JSON excludes cancelled events; .ics includes them (cancelled within the last 90 days) so subscribed phones remove them.
